---
title: "Recent hardware advances in low-cost precision network time"
---

Precision Time Protocol (PTP) has been widely adopted in many industries, such as telecom, finance and industrial automation, where its capabilities are essential. But it has been something that requires expensive, specialized hardware to deploy properly.
Typically the first step in a deployment has been to buy an off-the-shelf PTP grandmaster, which costs $1,000 and up.
This has made PTP unappealing in scenarios where it is not strictly required.

In this post, I want to highlight four relatively recent hardware advances that I think change the value proposition of PTP,
and make it potentially appealing to a broader audience.

1. Raspberry Pi Compute Module 4/5. The CM4 and CM5 both include a Broadcom PHY that supports timestamping of PPS inputs, and has Linux kernel support. This is the key capability that is needed to build your own PTP grandmaster. Before this, the only real option was the Intel i210-T1, which is getting quite old, and which as a PCIe card requires a much larger form-factor. The availability of the 40-pin header on the CM4/5 make it much easier to interface a wide variety of GPS modules. The CM4 has been out for several years, but it became unavailable for a long time during COVID. The main Raspberry Pi kernel got the necesssary kernel support for the CM5 only recently.

2. FS.com industrial switches with PTP transparent clocks. Synchronizing one client with one server is of limited utilty. Typically you want multiple clients and that means you need a switch. PTP is designed so that switches can support it at a hardware level, which means there is no loss of accuracy from using a switch. Using a switch without this support significantly degrades the accuracy achievable with PTP. Up until recently, switches with proper support for PTP transparent clocks cost thousands of dollars. But FS.com now offers switches like the IES3110-8TF-R, which cost between $150-$200 (depending on where you live), and have proper PTP transparent clock support. 

3. Precision Time Measurement (PTM) in the Intel i225/i226. PTP has focused on getting the PTP hardware clock (PHC) synchronized. Linux has a dynamic clocks feature that allows you to use a PHC as a POSIX clock, and specialized applications can use that. But most applications work with the system clock, and they will only get the benefit of greater accuracy if the system clock is more accurate. Up until recently, the accuracy with which the system clock can be synchronized to the PHC has been much lower than that with which a PHC can be synchronized with a grandmaster. PTM provides the hardware support that fixes this. Initially it became available on the i225, but kernel support was only available for the higher-end i225-LM variant and was disabled on the lower cost and more widely available i225-V variant. With the i226, PTM works on both the i226-V and i226-LM. PTM also requires motherboard support. Within the last couple of years, low cost devices with multiple i226-V interfaces and suitable 12th-gen motherboards that work with PTM have become available. These devices also allow bridging PTP networks without requiring specialized hardware where multiple network interfaces share a single PHC.

4. Low cost L1/L5 GNSS receivers. The largest source of error in GNSS-based timing comes from delays in the ionosphere and troposphere, which affect signals differently depending on frequency. Dual-frequency receivers can detect and correct for these disturbances, significantly improving timing accuracy. The first generation of dual-frequency receivers used the L1/L2 bands and were expensive. China's early operational deployment of the L5-equivalent signal in BeiDou-3 catalyzed the development of a new generation of multi-constellation L1/L5 receivers, at a price-point suitable for deployment in mass-market systems like smartphones, drones and smart driving systems. For example, the Allystar TAU1201 costs around $20 and gives timing performance which is competitive with the much more expensive earlier generation. 

With these hardware advances, it becomes much more affordable to deploy hardware that is capable of achieving network time synchronization with accuracy in the tens of nanoseconds.  SatPulse is designed to reduce the effort and cost needed to take advantage of these advances, by making it easy to deploy a fully-open source PTP grandmaster.

I think there is an opportunity for PTP to achieve much greater adoption. That of course needs applications that are compelling outside specialized industries. There's a lack of such applications currently. But developers can't easily build applications that rely on accuracy in the tens of nanoseconds if they cannot easily build a local network with the necessary capability. I hope that SatPulse in conjunction with these hardware advances can make PTP accessible to the interested and curious, and that this will in turn lead to new interesting experiments and applications.
