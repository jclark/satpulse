title: SatPulse 0.2 released
date: 2026-05-08 09:30:00 +0700
---

I have released [SatPulse 0.2](https://github.com/jclark/satpulse/releases/tag/v0.2). This is a major new release with a lot of new functionality (more than 60% of the code is new since 0.1).

Highlights of this release:

- there is a [new PHC synchronization architecture]({% link _posts/2026-05-05-evolving-a-new-phc-synchronization-architecture-for-satpulse-0.2.md %}), including a GNSS/PHC simulator (which has a [CLI]({% link man/satpulsetool-syncsim.1.md %}))
- it supports [seven vendor protocols in addition to UBX]({% link _posts/2026-04-01-a-tour-of-the-gps-modules-supported-by-satpulse.md %})
- it is evolving beyond the original PTP use case to become an [alternative to gpsd]({% link _posts/2026-04-11-design-of-satpulse-compared-with-gpsd.md %}) for some server-side use cases, in particular it can now be used as a [source of time for an NTP server]({% link _posts/2026-04-06-building-an-ntp-server-on-a-raspberry-pi-with-chrony-or-ntpd-rs.md %}) (either [chrony](https://chrony-project.org/) or [ntpd-rs](https://github.com/pendulum-project/ntpd-rs)) [without needing a PHC]({% link _posts/2026-04-01-using-satpulse-for-timing-without-a-phc.md %})
- it has had [extensive testing on a wide range of hardware]({% link _posts/2026-05-03-satpulse-0.2-hardware-test-matrix.md %})

I created a [discussion thread](https://github.com/jclark/satpulse/discussions/268) where you can ask questions, share experiences and suggest new features.
