# NTRIP caster: `gps/app/ntrip` (#126)

Implements an NTRIP caster that serves RTCM correction data from the
GPS receiver to connecting NTRIP clients (rovers).  Addresses issue
#126 and issue #236 (MSM7→MSM4 conversion).

## Configuration

The caster is configured via `[ntrip]` and `[[ntrip.mountpoint]]`
tables in `satpulse.toml`.  A single `[[ntrip.mountpoint]]` with
just a `name` is enough to get a working caster:

```toml
[[ntrip.mountpoint]]
name = "BKK"
```

Everything else is defaulted intelligently (see "Source table"
below for how each field is derived).  Operators only need to
add config when they want to override a default or restrict
access.

`[ntrip]` may also be configured without any mountpoints.  In
that case the caster does not start, but the section's STR-record
fields (country, lat, lon, generator, formatDetails, bitrate,
network) are used as defaults by `[[stream.push]]` entries that
upload to a remote NTRIP caster.  See `plan/ntrip-server.md`.

Full configuration:

```toml
[[user]]
name = "rover1"
password = "secret"

[[user]]
name = "rover2"
password = "secret2"

[ntrip]
listen = ":2103"       # default ":2101"
country = "THA"        # source-table country override; default "XXX"
network = "MyNet"      # source-table network override; default "Misc"
lat = 13.76            # override Mode-derived latitude; pair with lon
lon = 100.50           # override Mode-derived longitude; pair with lat
generator = "..."      # source-table generator override; default below
formatDetails = "..."  # source-table format-details override; default derived
bitrate = 9600         # default per-mountpoint bitrate; default 0

[[ntrip.mountpoint]]
name = "BKK"
description = "Bangkok"   # source-table identifier; default = name
bitrate = 4800            # override [ntrip].bitrate for this mountpoint
auth.users = ["rover1"]   # require auth, only rover1

[[ntrip.mountpoint]]
name = "BKK4"
msm7to4 = true            # convert MSM7 to MSM4
auth.anyUser = true       # require auth, allow any top-level user
```

Rules:

- `listen` defaults to `":2101"` (IANA-assigned NTRIP port).
- The caster is started only when at least one
  `[[ntrip.mountpoint]]` is specified.  `[ntrip]` alone (with no
  mountpoints) is a valid configuration -- it supplies STR-record
  defaults to `[[stream.push]]` entries.
- Mountpoint `name` per the v2 spec is "Characters, 100 max,
  restricted to A-Z, a-z, 0-9, -, ., and _" (no slashes -- it
  is a single URL path component).
- Authentication is configured per mountpoint using the `auth`
  object; see "Authentication".
- `ntrip.lat` and `ntrip.lon` must be set together or not at all;
  configuring just one is a validation error.
- `msm7to4 = true` converts MSM7 packets to MSM4 before sending.
  Non-MSM7 RTCM packets are forwarded unchanged.  The mountpoint's
  STR record is generated by transforming `formatDetails` -- MSM7
  message numbers (`1077, 1087, ...`) are replaced with MSM4
  numbers (`1074, 1084, ...`).

## Authentication

Top-level `[[user]]` entries define reusable credentials.  They
do not, by themselves, enable NTRIP authentication; future HTTP
endpoints can reuse the same user registry without changing NTRIP
mountpoint access.

Each NTRIP mountpoint has an optional `auth` object:

```toml
[[ntrip.mountpoint]]
name = "OPEN"

[[ntrip.mountpoint]]
name = "ANY_USER"
auth.anyUser = true

[[ntrip.mountpoint]]
name = "ROVER1"
auth.users = ["rover1"]

[[ntrip.mountpoint]]
name = "CLOSED"
auth.users = []

[[ntrip.mountpoint]]
name = "ALSO_CLOSED"
auth = {}
```

Authentication rules:

1. A mountpoint requires authentication if and only if `auth` is
   non-nil.
2. When authentication is required, authorization passes if and
   only if either `auth.anyUser = true` and the credentials match
   any top-level user, or the credentials match a top-level user
   whose name is in `auth.users`.
3. It is a config error for `auth.anyUser = true` and
   `auth.users` to be non-empty.

An empty `auth.users` list, or an empty `auth` object written as
`auth = {}`, is therefore a closed mountpoint: authentication is
required but no user is authorized.

Possible future extension: add `auth.passwordFile` pointing to an
Apache htpasswd-style file with hashed passwords.  That would allow
operators to keep password hashes outside `satpulse.toml` while
preserving the same per-mountpoint `auth` object as the policy
switch.

## Source table

The source table contains one `STR` record per configured
mountpoint.  Field 1 (`STR`) and field 2 (`<mountpoint>`) are
emitted by the caster runtime as `STR;<name>;` prefix; the
remaining 16 fields plus the trailing `<misc>` field are produced
by the closure returned by `StreamRecordBuilder` (so the closure
output is "fields 3..n", suitable both for the source-table line
prefix and for the SOURCE upload's `STR:` header).

| # | Field | Override | Default |
|---|-------|----------|---------|
| 1 | STR | -- | literal `STR` (emitted by caster runtime as the line prefix) |
| 2 | mountpoint | -- | `ntrip.mountpoint.name` (emitted by caster runtime) |
| 3 | identifier | `ntrip.mountpoint.description` | `ntrip.mountpoint.name` |
| 4 | format | -- | `RTCM 3.3` |
| 5 | format-details | `ntrip.formatDetails` | derived (see below); only synthesised when `StreamRecordBuilder` is called with `msm > 0`. For mountpoints with `msm7to4 = true`, MSM7 message numbers in the resolved string are substituted with MSM4 numbers before emission. |
| 6 | carrier | -- | derived from enabled signals: `2` if any non-L1 signal (L2 or L5) is enabled, else `1` if only L1 signals, else `0`. Spec defines only `0`/`1`/`2`; `2` is the only "multi-frequency" value, used for any L1+L2/L1+L5/etc. |
| 7 | nav-system | -- | derived from enabled GNSS, e.g. `GPS+GLO+GAL+BDS` |
| 8 | network | `ntrip.network` | `"Misc"` (the spec's example placeholder for stations not part of a formal network) |
| 9 | country | `ntrip.country` | `"XXX"` (ISO 3166 user-assigned range; conventional "unknown" placeholder) |
| 10 | latitude | `ntrip.lat` (paired with `ntrip.lon`) | from `Mode.FixedPosECEF` via `geopos.WGS84.ECEFtoLLH`, or `Mode.FixedPosLLH[0]` directly; else from a `PosGeoMsg` opportunistically captured during `gpscfg.Configure` (see "Live-position capture"); else `0.00` |
| 11 | longitude | `ntrip.lon` (paired with `ntrip.lat`) | same source as lat; else `0.00` |
| 12 | nmea | -- | `0` (no VRS support) |
| 13 | solution | -- | `0` (single base) |
| 14 | generator | `ntrip.generator` | `ReceiverInfo.Hardware` if we have ReceiverInfo and the field is non-empty (e.g. `ZED-F9T`); else `cmd.VersionInfo()` (e.g. `satpulse version 0.2.0`); else `"satpulse"`. Spec says field is "Hard- or software generating data stream"; receiver-model convention dominates spec examples. |
| 15 | compr-encryp | -- | `none` |
| 16 | authentication | -- | `B` if this mountpoint has an `auth` object, else `N` |
| 17 | fee | -- | `N` |
| 18 | bitrate | `ntrip.mountpoint.bitrate` | `ntrip.bitrate` if set, else `0` |
| -- | misc | -- | `""` |

### Default for format-details (field 5)

Synthesised from the enabled GNSS set as `MSM<msm>` messages
plus 1005 plus 1230 (when GLO is enabled), all at update rate
`(1)`.  `<msm>` is the `msm` argument passed to
`StreamRecordBuilder`; typically `4` or `7`, or `0` to suppress
synthesis entirely.

For `msm = 4` and a typical GPS+GLO+GAL+BDS configuration:

```
1005(1),1074(1),1084(1),1094(1),1124(1),1230(1)
```

For `msm = 7`, the same configuration becomes:

```
1005(1),1077(1),1087(1),1097(1),1127(1),1230(1)
```

MSM message numbers per constellation: `107x` GPS, `108x` GLO,
`109x` GAL, `110x` SBAS, `111x` QZSS, `112x` BDS, `113x` NavIC,
where `x = msm`.  Only MSM messages for constellations in the
enabled GNSS set are included.  `1230` (GLONASS code-phase bias)
is included only when GLO is enabled.

Limitations:

- The MSM number assumes satpulse knows which MSM type the
  receiver is emitting.  Today the daemon picks `4` when
  `gps.rtcmOutput = true` (the typical pick for modern receivers)
  and `0` otherwise.  Once issue #203 lands and `ReceiverInfo`
  reports MSM4/MSM7 capability, the daemon can pass the actual
  configured MSM type.
- Synthesis hard-codes major-GNSS-only MSM, which is correct for
  u-blox but understates the stream for Unicore receivers (which
  also emit QZSS MSM 1114/1117 when QZSS is enabled).  Once issue
  #203 lands and `ReceiverInfo` reports per-vendor MSM-output GNSS,
  the synthesis can match what each receiver actually emits.
- Assumes only the messages satpulse configures are emitted.  If
  the operator has manually configured the receiver to emit
  additional message types (or `gps.config = false` and the
  receiver was configured externally), those types will not
  appear.

In both cases the operator can set `ntrip.formatDetails`
to provide the correct value.

### Live-position capture

When neither `ntrip.lat`/`lon` nor `gps.fixedPos*` is set, the
STR record falls back to a `PosGeoMsg` opportunistically
captured during `gpscfg.Configure`.  The daemon installs a
`configCapture` MsgHandler (extension of the existing
`leapSecondCapture` pattern in `time/app/daemon/daemon.go`)
before calling `gpscfg.Configure`; its `PosGeo` method stores
the latest message.  After `Configure` returns, the captured
position (or `nil` if no fix was seen) is passed to
`StreamRecordBuilder` as `configCapturePos`.

This is opportunistic: one-shot, captured only during the
config sweep, never updated afterwards.  Cold survey-in (no
fix during config) still emits `0.00`; the operator override
remains the escape hatch.  The same captured value is reused
by NTRIP `[[stream.push]]` entries (see `plan/ntrip-server.md`).

### Validation of formatDetails

`Config.FormatDetails` (whether set by the operator or
synthesised by `StreamRecordBuilder`) must match the regex:

```
^[A-Za-z0-9_]+(\([0-9]+\))?(,[A-Za-z0-9_]+(\([0-9]+\))?)*$
```

That is: comma-separated entries, each an alphanumeric/underscore
token optionally followed by `(<digits>)` for the update rate in
seconds.  This matches both what we synthesise (RTCM message
numbers) and the spec examples for non-RTCM formats (e.g.
`Compact(1)`).  Validation is performed once during caster
startup; an invalid value is a fatal config error.

### Defaulting

See "StreamRecordBuilder" under "Types" below for the closure
constructor.  Both the caster (per mountpoint) and the daemon
(per NTRIP `[[stream.push]]` entry) call the returned closure
to obtain fields-3..n STR strings.

## NTRIP protocol

We support both NTRIP v1 and v2 with auto-detection.  The server
uses Go's `net/http.Server` for request parsing, auth, and routing.
The response path differs by version.

**Version detection:**

The client's NTRIP version is determined by the `Ntrip-Version`
header.  If the request includes `Ntrip-Version: Ntrip/2.0`, the
client is treated as v2.  Otherwise, it is treated as v1.  This is
more reliable than checking `r.ProtoMinor`, since some v1 clients
send HTTP/1.1 requests.

**V1 response:**

The handler uses `http.Hijacker` to take over the raw connection
and writes exactly `ICY 200 OK\r\n` (12 bytes, single CRLF)
followed by the raw RTCM byte stream.  No further headers, no
blank line.  Appendix C of the v1 spec strictly checks the
12-byte length, so the second CRLF some implementations send is
non-conforming.

**V2 response:**

The handler uses `http.ResponseWriter` with
`http.NewResponseController.Flush()` to stream data.  Go
automatically applies `Transfer-Encoding: chunked` since
Content-Length is unknown.  Headers set on the response:

- `Content-Type: gnss/data`
- `Cache-Control: no-store, no-cache, max-age=0`
- `Pragma: no-cache`
- `Connection: close`
- `Server: NTRIP satpulse/<version>`
- `Ntrip-Version: Ntrip/2.0`

`Date` is added by Go's HTTP server automatically.

HTTP/2 is disabled on this server (set `TLSNextProto` to empty map)
since NTRIP v2 means HTTP/1.1, not HTTP/2, and Go's HTTP/2
response writer does not support hijacking.  The v2 spec also
states that NTRIP uses only non-persistent connections, so we
always send `Connection: close`.

**Source table request** (`GET /`):

The caster responds with the NTRIP source table, listing each
configured mountpoint as one `STR` line and terminating with
`ENDSOURCETABLE\r\n`.  Body content is identical between v1 and
v2; the response framing differs.

V1: hijack the connection (because the status line is non-HTTP)
and write:

```
SOURCETABLE 200 OK\r\n
Server: NTRIP satpulse/<version>\r\n
Content-Type: text/plain\r\n
Content-Length: <decimal octets>\r\n
\r\n
<body including ENDSOURCETABLE\r\n>
```

`Content-Length` counts the body bytes including the trailing
`ENDSOURCETABLE\r\n`.  This is also the v1 fallback for an
unknown mountpoint (the v1 spec requires sending the source
table rather than a 404).

V2: normal `HTTP/1.1 200 OK` via `http.ResponseWriter`, with
headers:

- `Content-Type: gnss/sourcetable`
- `Ntrip-Version: Ntrip/2.0`
- `Ntrip-Flags:` (empty -- we advertise no optional features)
- `Server: NTRIP satpulse/<version>`
- `Connection: close`
- `Content-Length: <decimal octets>`

Body identical to v1.  `Date` is added by Go automatically.

V2 unknown mountpoint is a normal 404 (not the sourcetable).

**Stream request** (`GET /<mountpoint>`):

The handler looks up the mountpoint, checks basic auth when that
mountpoint has an `auth` object, detects the NTRIP version, and
responds accordingly.  It then streams raw RTCM data until the
client disconnects or the context is cancelled.

**Auth:**

HTTP basic auth via `r.BasicAuth()`, following the rules in
"Authentication".

On auth failure the caster sends 401 with the `WWW-Authenticate:
Basic realm="/<mountpoint>"` header (the realm value includes the
leading slash, in double quotes).  This header is required by
both v1 and v2 specs.  In the v1 case the response is a
`HTTP/1.0 401 Unauthorized` line with HTML body; in the v2 case
it is a normal `HTTP/1.1 401` -- both are produced via
`http.Error` plus a `WWW-Authenticate` header.

**NMEA GGA from client (VRS):**

Both v1 and v2 allow a rover to send `$GPGGA` (and other NMEA)
sentences to the caster on the same socket after the request, to
support virtual reference station (VRS) mountpoints.  v2 also
allows an `Ntrip-GGA` request header.  We do not implement VRS in
this caster: configured mountpoints serve a single broadcast
stream regardless of rover position.  The handler must not block
or fail if a client sends GGA -- ignore the request body and any
`Ntrip-GGA` header.

**Filtered source-table requests:**

v2 clients may issue `GET /?match=...`, `GET /?filter=...`, or
similar.  The v2 spec requires casters that do not implement
filtering to still recognise these requests and return the
unfiltered source table (not 404).  Treat any `GET /` with a query
string the same as `GET /` with no query string.

## Architecture

The caster is a fan-out model: one source (the receiver's packet
bcast), many subscribers (connected clients).  Each client gets its
own goroutine that subscribes to the bcast, filters to RTCM packets,
optionally converts MSM7→MSM4, and writes to the TCP connection.

This is similar to `proxy.connWriteWorker` but with:

- RTCM-only filtering (using `scan.Packet.HasTag(gpsreg.TagRTCM)`)
- Optional MSM7→MSM4 conversion per mountpoint
- NTRIP HTTP framing on connection setup
- Auth and mountpoint routing

No pruning queue is needed: each client has its own TCP connection
with OS buffering.  If a client can't keep up, the bcast drops
messages for that subscriber (bcast's existing behavior) or the TCP
write blocks/errors and we disconnect the client.

## Package: `gps/app/ntrip`

Lives at the application layer in `gps/app/` alongside `bcast`,
`gpsio`, and `stream`.  It does logging and manages goroutines,
so it belongs at the app layer, not in `gps/lib/`.

### Dependencies

- `gps/app/bcast` -- subscribe to receiver's packet stream
- `gps/scan` -- `scan.Packet` type
- `gps/gpsreg` -- `TagRTCM` for filtering
- `gps/lib/rtcmbin` -- `ParseMsg`, `MSM7Convert`, `SerializeMsg`,
  `ExtractMsgType`, `MsgType.IsMSM`
- `gps/lib/geopos` -- `WGS84.ECEFtoLLH` for source-table lat/lon
- `gps/gpsprot` -- `Tag`, `ConfigProps`, `GNSSSet`

NTRIP framing (version detection from request headers, response
status lines, source-table formatting) is handled inline in this
package.  It is small and caster-specific.  We follow the
precedent set by `NTRIPSource` in `gps/app/stream`, which keeps
its v1 handshake inline rather than depend on a shared
`gps/lib/ntriphdr` package.

### Types

```go
// SharedStreamConfig holds the global STR-record fields that
// apply to every stream served from this satpulse instance,
// whether by the caster or by stream.push entries.  Embedded in
// ntrip.Config; referenced by NTRIPPushConfig in gps/app/stream.
//
// All fields are operator-overridable.  StreamRecordBuilder
// resolves unset fields from gps state at construction time but
// does not mutate this struct.
type SharedStreamConfig struct {
    Country       string                 `toml:"country"`
    Network       string                 `toml:"network"`
    Lat           opt.Val[gpsprot.Angle] `toml:"lat"`
    Lon           opt.Val[gpsprot.Angle] `toml:"lon"`
    Generator     string                 `toml:"generator"`
    FormatDetails string                 `toml:"formatDetails"`
    Bitrate       int                    `toml:"bitrate"`
}

// StreamConfig holds the per-stream STR-record fields, embedded
// in both ntrip.MountConfig (caster) and stream.NTRIPPushConfig
// (push destination).  All fields are operator-overridable; the
// builder closure reads them but does not mutate them.
type StreamConfig struct {
    Description string `toml:"description"`
    Bitrate     int    `toml:"bitrate"`
    // MSM7to4 added in step 7 (later)
}

// Config is the TOML configuration for the NTRIP caster.

}

type MountConfig struct {
    Name         string   `toml:"name"`

    AnyUser bool     `toml:"anyUser"`
    Users   []string `toml:"users"`

```

### StreamRecordBuilder

A pure function that returns a closure for building STR-record
strings:

```go
// StreamRecordBuilder returns a closure that builds STR-record
// fields-3..n strings.  The constructor reads from *shared and
// from gps state, derives nav-system and carrier from enabled
// signals, and captures the resolved values plus everything
// else needed in the closure.  Neither the constructor nor the
// closure mutates *shared or *StreamConfig.
//
// shared supplies the operator-set global STR fields.  Unset
// fields in shared are resolved by the constructor:
//   - Lat/Lon (operator sets both or neither; Config.Validate
//     rejects half-set): if both set, used as-is; else from
//     props.GetMode() (PosTypeECEF via geopos.WGS84.ECEFtoLLH;
//     PosTypeLLH directly); else from configCapturePos.LatLon
//     when non-nil; else (0, 0)
//   - Generator from info.Hardware, else versionInfo, else
//     "satpulse"
//   - FormatDetails from enabled signals + msm, when msm > 0
// nav-system and carrier are derived from enabled signals
// (carrier: 2 if any non-L1 signal, else 1 if any L1, else 0).
//
// info or props may be nil; an empty versionInfo is allowed.
// msm is 0 to skip format-details synthesis, or 4/7/etc.
// configCapturePos is an opportunistic PosGeoMsg captured
// during gpscfg.Configure; nil if no fix was seen.
//
// The returned closure takes a per-stream StreamConfig, the
// stream's mountpoint name, and whether that stream requires
// client authentication.  It returns "fields 3..n" of the STR
// record (semicolon-separated, no leading "STR;<name>;", no
// trailing CRLF).  This format suits both:
//   - The caster source-table line, where the runtime emits
//     "STR;<name>;" + closureResult + "\r\n"
//   - The SOURCE upload's STR: header in stream.push, where the
//     wire format is "STR: " + closureResult + "\r\n" (per the
//     v1 spec, which says STR-string is fields 3..n only).
//
// The closure uses sc.Description (default = name) and
// sc.Bitrate (default = shared.Bitrate) without mutating *sc.
func StreamRecordBuilder(
    shared *SharedStreamConfig,
    props *gpsprot.ConfigProps,
    info *gpsprot.ReceiverInfo,
    versionInfo string,
    msm int,
    configCapturePos *gpsprot.PosGeoMsg,
) func(sc *StreamConfig, name string, hasAuth bool) string
```

The daemon must set `target.Get |= gpsprot.PropIDSignalsEnabled
| gpsprot.PropIDMode` in `GPSConfig.target` when `[ntrip]` is
configured, so that `props` carries the signals and mode after
`gpscfg.Configure` returns.

### Start function

```go
func Start(ctx context.Context, lg *slog.Logger,
    wg *sync.WaitGroup, cfg Config, users map[string]string,
    b *bcast.Bcast[scan.Packet],
    buildSTR func(sc *StreamConfig, name string, hasAuth bool) string,
) error
```

`buildSTR` is the closure returned by `StreamRecordBuilder`.
`Start` calls it once per mountpoint at startup, prepends
`"STR;" + name + ";"` to each result, and stores the
resulting line-prefixed strings in caster runtime state to be
served as part of the source-table response.  After startup the
closure is not retained.  The `hasAuth` argument passed to the
closure is `true` when the mountpoint has a non-nil `auth`
object.

`users` maps top-level user names to passwords.  It is owned by
the daemon's top-level config and passed into the caster so the
NTRIP package does not own the global user registry.

Follows the same pattern as `proxy.Start` and `startHTTP`:

1. Listen on TCP.
2. Start accept loop goroutine via `wg.Go`.
3. Start shutdown goroutine that closes listener on ctx cancel.
4. Return.

`Start` assumes the configuration is internally consistent.  The
caller is responsible for calling `cfg.Validate(users)`, where
`users` is the set of top-level user names; this checks that
every mountpoint has a valid name with no duplicates, that
`auth.users` entries resolve to defined users, and that
`auth.anyUser` is not combined with a non-empty `auth.users`
list.  In the daemon, this happens during
`daemon.Config.Validate` well before `Start` is invoked.

### Connection handling

Connections are handled by `net/http.Server`.  The handler
registered on the mux dispatches based on the request path:

1. `GET /` (with or without a query string): respond with source
   table, close connection.
2. `GET /<path>`: detect NTRIP version from `Ntrip-Version`
   header, then look up mountpoint.
   - If auth required and missing/invalid: 401 with
     `WWW-Authenticate` (see "Authentication").
   - If mountpoint not found:
     - v1: respond with the source table (the v1 spec specifies
       this fallback rather than an error).
     - v2: 404.
   - V1 success: hijack connection, write `ICY 200 OK\r\n`
     (12 bytes), stream.
   - V2 success: write headers via `ResponseWriter`, stream with
     `ResponseController.Flush()`.

### Streaming

The streaming logic is the same for both v1 and v2 -- only the
writer differs (`net.Conn` for v1, `http.ResponseWriter` for v2).
Both paths call a common function that takes an `io.Writer` and
an optional flush function:

1. Subscribe to bcast.
2. Loop: receive packet from subscription channel.
3. Skip if not RTCM (`!pkt.HasTag(gpsreg.TagRTCM)` or
   `!pkt.ChecksumValid`).
4. If `mount.MSM7to4` and packet is MSM7: parse, convert,
   re-serialize.  Non-MSM7 packets pass through unchanged.
5. Write packet data.  Flush if v2.
6. On write error or ctx cancel: unsubscribe, return.

### MSM7→MSM4 conversion

For a mountpoint with `msm7to4 = true`:

```go
mt := rtcmbin.ExtractMsgType(pkt.Data)
if mt.IsMSM() && mt%10 == 7 {
    m7, err := rtcmbin.ParseMsg(pkt.Data)
    if err != nil { /* forward original */ }
    m4, err := rtcmbin.MSM7Convert(m7.(*rtcmbin.MSMHiRes), 4)
    if err != nil { /* forward original */ }
    data, err := rtcmbin.SerializeMsg(m4)
    if err != nil { /* forward original */ }
    // write data instead of pkt.Data
}
```

On conversion error, forward the original packet unchanged -- a
degraded MSM7 is better than no data.

## Daemon integration

In `time/app/daemon/`:

1. Add reusable top-level users and NTRIP config to the daemon
   `Config` struct:
   ```go
   type Config struct {
       Users []UserConfig `toml:"user"`
       Ntrip ntrip.Config `toml:"ntrip"`
       // ...
   }

   type UserConfig struct {
       Name     string `toml:"name"`
       Password string `toml:"password"`
   }
   ```
   Validate that user names are non-empty and unique.  Also
   validate that every `auth.users` entry on an NTRIP mountpoint
   references a top-level user.
2. In `GPSConfig.target` (`gps.go`), when `[ntrip]` is
   configured, set
   `target.Get |= gpsprot.PropIDSignalsEnabled | gpsprot.PropIDMode`
   so the caster can read enabled signals (for nav-system,
   carrier, format-details) and the position (for lat/lon) back
   from the receiver after `gpscfg.Configure` runs.
3. In `run()`, after the packet bcast is created and
   `gpscfg.Configure` has returned `gcfg`, build the
   `StreamRecordBuilder` closure once if `[ntrip]` is configured,
   then use it for both the caster (when mountpoints exist) and
   for each NTRIP `[[stream.push]]` entry's STR header.  `cc` is
   the `configCapture` handler already installed before
   `gpscfg.Configure` (see "Live-position capture" above);
   `cc.pos` carries any `PosGeoMsg` captured during the config
   sweep, or `nil`.
   ```go
   if /* [ntrip] configured */ {
       msm := 0
       if cfg.GPS.Config && cfg.GPS.RTCMOutput != nil && *cfg.GPS.RTCMOutput {
           msm = 4
       }
       users := userPasswordMap(cfg.Users)
       buildSTR := ntrip.StreamRecordBuilder(
           &cfg.Ntrip.SharedStreamConfig,
           gcfg.ConfigProps, gcfg.ReceiverInfo, cmd.VersionInfo(), msm,
           cc.pos)
       if len(cfg.Ntrip.Mountpoint) > 0 {
           ntrip.Start(ctx, lg, wg, cfg.Ntrip, users, pktBcast, buildSTR)
       }
       for i := range cfg.Stream.Push {
           pe := &cfg.Stream.Push[i]
           if pe.NTRIP != nil {
               pe.NTRIP.STR = buildSTR(&pe.NTRIP.StreamConfig, pe.NTRIP.Mountpoint, false)
           }
       }
   }
   ```
4. No `portLock` needed -- the caster is read-only.

## Testing

Tests use `net.Pipe` or a local TCP listener on localhost.

- Source table: connect, `GET /`, verify source table lists
  mountpoints.
- Stream: connect, `GET /RTCM`, send RTCM packets into bcast,
  verify they arrive on the connection.
- Auth: verify anonymous mountpoints do not require credentials;
  `auth.anyUser = true` accepts any valid top-level user;
  `auth.users = ["rover1"]` accepts only that user; an empty
  `auth.users` list rejects every user; invalid credentials
  return 401.
- Auth validation: verify duplicate top-level user names,
  undefined `auth.users` entries, and `auth.anyUser = true` with
  non-empty `auth.users` are config errors.
- MSM7→MSM4: send MSM7 packet into bcast, verify client receives
  MSM4.
- Mountpoint not found: verify 404.
- Client disconnect: verify goroutine cleans up.
