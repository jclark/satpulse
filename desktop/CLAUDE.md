# Desktop GUI development

Wails v2 app with a Preact + TypeScript + Vite frontend and Go backend.

## Dev server

The user starts `wails dev` in a terminal:

```
cd desktop && wails dev
```

This starts two servers:
- **Vite dev server** (typically `localhost:5173`) -- serves frontend assets with HMR
- **Wails dev server** (`localhost:34115`) -- proxies frontend and provides Go backend bindings

**NEVER start or stop `wails dev` yourself.** The user manages it. If a task will require browser testing, check that `localhost:34115` is reachable at the **start** of the task (before writing code). If it is not running, ask the user to start it in a terminal before proceeding.

**NEVER run Vite directly** (`npm run dev`, `npx vite`, etc.). Wails manages the Vite dev server internally. Running Vite separately creates a standalone frontend at `localhost:5173` with no Go backend -- all Go calls will fail.

**NEVER use `localhost:5173` for testing.** Always use `localhost:34115`.

Vite supports Hot Module Reload and picks up file changes instantly -- there is no need to restart after editing frontend code.

## Verifying UI changes

A Playwright MCP server is configured in `/.mcp.json`. Use Playwright to navigate to `http://localhost:34115` and take screenshots to verify the rendered page.

## Frontend structure

The UI components live in the shared workbench package
(`webui/packages/workbench`), consumed as the `@satpulse/workbench`
`file:` dependency. See that package's `src/CLAUDE.md` for the
frontend code style (semantic design tokens, component primitives).
`desktop/frontend` contains only the entry point and the Wails
implementation of the workbench transport interface:

```
frontend/
  index.html            -- Vite entry point
  vite.config.ts        -- Vite + Preact + Tailwind plugins
  package.json          -- npm dependencies
  src/
    main.tsx            -- installs the transport, renders App
    wails-transport.ts  -- Transport implementation over Wails bindings
  wailsjs/              -- auto-generated by Wails, do not edit
    go/main/App.d.ts    -- TypeScript types for Go backend methods
    go/models.ts        -- TypeScript types for Go structs
    runtime/            -- Wails runtime (events, window control, etc.)
```

## Go backend bindings

The Go side (`app.go`) is a thin shell over `gps/app/session`: a Sink
forwarding session events to the Wails event bus, plus bindings
adapting session methods to the frontend. Exported methods on the
`App` struct are callable from the frontend; Wails auto-generates
TypeScript bindings in `frontend/wailsjs/go/`. The frontend never
calls the bindings directly -- everything goes through
`src/wails-transport.ts`, which implements the transport interface in
`webui/packages/workbench/src/transport.ts`.

## Tailwind CSS

Uses Tailwind 4.x via `@tailwindcss/vite` plugin. Styles come from the
workbench package (`@satpulse/workbench/src/style.css`), which defines
the semantic design tokens; never use hardcoded colour classes or
`dark:` prefixes (see the workbench `src/CLAUDE.md`).

## Build

```
cd desktop && make                      # full app (SatPulse.app on macOS, SatPulse on Linux)
cd desktop/frontend && npm run build    # frontend only (tsc + vite build)
```

The workbench `file:` dependency resolves through the `webui/` npm
workspace, so `npm install` must have been run in `webui/` first
(`make` does this automatically).

On Linux the `Makefile` adds `-tags webkit2_41` automatically (only the
WebKitGTK 4.1 headers are packaged on current distros). See the README
prerequisites for the GTK/WebKitGTK packages to install.

The Go embed directive in `main.go` embeds `all:frontend/dist`.
