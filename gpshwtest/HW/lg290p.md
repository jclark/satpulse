# LG290P limitations

How device-independent configuration is realized on the Quectel
LG290P, relative to perfect realization of the full model
(`SEMANTICS.md`). Measured on firmware LG290P03AANR02A01S (2025/12/12,
UART-to-USB bridge at 460800). All configuration is NMEA-text PQTM
sentences; the receiver has no binary protocol.

## Starting state

Factory defaults except the time pulse in only-when-locked mode, saved
to NVM; `setup/lg290p.sh` establishes it. The pulse mode matters:
`--pps` requests only-when-locked by design and the CLI has no flag to
set the mode back, so gpshwtest can restore what it finds only if the
starting state is only-when-locked. (The factory default is
pulse-always, which a run cannot restore after probing `--pps`.)

## Stored-only settings (the onlyWithReset qualifiers)

The defining limitation of this receiver: three groups of settings are
acknowledged and stored but take effect only when the configuration is
saved to NVM and the receiver reset (PQTMSAVEPAR then PQTMSRR, ~15 s
outage). satpulsetool performs them only when `--save` is combined
with `--reload` or `--reset`, otherwise skipping them (with a warning
when the skip leaves the receiver differing from the request):

- `signalOnlyWithReset`: signal and constellation enables
  (PQTMCFGSIGNAL/PQTMCFGCNST).
- `modeOnlyWithReset`: positioning mode (PQTMCFGRCVRMODE/PQTMCFGSVIN).
- `rtcmMSMOnlyWithReset`: the RTCM MSM type (4 versus 7, PQTMCFGRTCM).
  Message enabling and disabling is live; only the type switch needs
  the reset - verified even for messages freshly enabled after an
  acknowledged type change.

Signal and mode probing therefore runs only on `--disruptive` runs,
with `--save --reload` per case.

## Positioning mode

Position modes (survey-in and fixed) exist only under base receiver
mode: a stored SVIN mode is inert in rover mode, readback-verified.
Entering base mode swaps to a per-mode message table (factory base
table: RTCM3 1005/1033/MSM4 only, no NMEA) and forces a 1 Hz fix
rate; message enables remain live in base mode. The surveyed position
never appears in configuration readback - PQTMSVINSTATUS is its only
carrier - so a saved survey-in mode re-surveys at every boot. Fixed
positions are ECEF only (LLH requests are converted client-side);
fixed-position accuracy has no carrier (`fixedPosAcc` absent).

## Signals

Readback reports stored intent, not effective state, and the receiver
stores masks it will not apply: L1-band bits cannot be disabled (spec
note, hardware-verified for GPS L1 C/A - a stored L1-off mask survives
save+reset with L1 still tracked while readback claims it off). By
owner ruling satpulsetool does not fix up or refuse such requests; it
writes what was asked and reports what the receiver says. Priority is
CNST > SIGNAL: a constellation gated off ignores its signal mask, so
constellation disables are gate-only with masks preserved. The
CFGSIGNAL bit universe is GPS L1/L2C/L5, GLONASS L1/L2, Galileo
E1/E5a/E5b/E6, BDS B1I/B2I/B3I/B1C/B2a/B2b, QZSS L1/L2C/L5/L6 (L6 from
R01A05S), NavIC L5; SBAS has no control at all.

## Time pulse

Width 0-900 ms only, quantized to 1 ms; the period is fixed at 1 s
(satpulsetool refuses other periods). The PQTMCFGPPS2 form documents a
(0, Period] duration range but hardware rejects widths over 900 ms
there too, so widths in (0.9, 1.0) s are refused by the receiver. A
disabled pulse reads back truncated: only the zero width is knowable
while disabled. No pulse-alignment knob exists (always aligned to GNSS
time), and no antenna cable delay or timing-constellation selection
(`antennaCableDelay` and `timeGNSS` absent).

## Message output

No raw observation or navigation output exists (`raw` absent; RTCM MSM
is the only observation carrier). No time-pulse message and no TAI or
ECEF content selectors, and no leap-second announcement carrier - the
PQTMPVT LeapS field carries the current GPS-UTC offset (delivered as
time-event UTCOffset) but nothing announces a pending leap, so the
`leap`, `tp`, `tai`, and `ecef` information kinds are missing from
PVT output. Message-rate tables are per-mode: a message enabled in
rover mode does not appear in the base-mode table and vice versa, and
setting a mode-foreign message is refused.

## Operations

Save is single-scope (PQTMSAVEPAR saves everything; `--save` is
indistinguishable from `--save-all`). `--reload` is realized as
PQTMSRR: a full reboot, silent for ~15 s, after which NVM contents are
in effect. A baud-rate change produces no acknowledgement at the old
rate (the port switches ~2 ms after the request); satpulsetool
switches speed after sending and confirms at the new rate.
