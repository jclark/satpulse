# AT632-6T-30 / AT362-AT6668-6T-30 (URANUS6 V6.3.0.0)

CASIC timing receiver, single band, UART at 115200. The hardware
string says AT362 although the product is sold as AT632-6T-30.
Characterized 2026-06-13, re-characterized 2026-07-21 (disruptive);
baseline `AT362-AT6668-6T-30-URANUS6,V6.3.0.0.json`.

## Limitations relative to the model

- Signals: L1-band only - GPS L1, GAL E1, BDS B1I+B1C, GLO L1,
  QZSS L1, SBAS L1. Requests for L5-band signals drop out via the
  chip's clamp of the reception mask. The same refusal rules as the
  F8N apply (augmentation-only or empty sets are refused).
- Leap second output (`leap`): TIM2-LS IS emitted, continuously at
  roughly one per second per monitored constellation, but only when a
  non-GPS constellation is enabled - a GPS-only selection emits none.
  Measured 2026-07-22: 60 packets in 30 s with GPS+BDS active (half
  all-zero RaimType 0, half RaimType 1 carrying the current leap,
  Dtls==Dtlsf), zero in 15 s with `--gnss GPS`. The characterization
  runs recorded leap as undelivered ("nothing appears within an
  observation window"); given the GPS-only behavior, the probe most
  plausibly observed while an earlier signal probe had left a
  GPS-only selection. The baseline still carries the leap-missing
  entry until a re-characterization. No pending-leap-event content
  (RaimType 2) is obtainable without a scheduled leap. Unlike the
  F8N, pulse-time (`tp` via TIM2-TPX) and survey progress (`survey`
  via TIM2-TIMEPOS) ARE delivered, and raw output (RXM2-MEASX/SFRBX)
  flows.
- RTCM output: CFG-RTCM is NAKed - RTCM configuration does not exist
  in this firmware (the port protocol-mask RTCM bit does stick).
  rtcmBaseID does not exist in the protocol.
- Fixed position: ECEF in 1 cm steps, accuracy in 1 mm steps; LLH
  requests realized as ECEF (LLH never reads back).
- Time pulse width quantized to 1 us.
- Reload: unsupported (V6 firmware); unsaved changes survive a
  `--reload`.
- Save granularity: a single group - saving anything saves everything.
- Active port: not identifiable (one port-query response per UART,
  nothing marks the current one).
