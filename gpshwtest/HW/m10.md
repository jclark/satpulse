# EVK-M101 (M10 SPG 5.10) limitations

How device-independent configuration is realized on the u-blox EVK-M101 evaluation kit (M10 standard precision, SPG 5.10, PROTVER 34.10), relative to perfect realization of the full model (`SEMANTICS.md`). Measured 2026-06-11, UART via CH340 bridge at 38400 (session raised to 115200). The M10 interface description is not in `../gps-protocol-docs/`, so vetting is by plausibility against the shared val-layer behavior and known M10 capabilities.

## Capabilities and properties

- `supports` is just `speed`: a standard-precision part - no survey/fixed-position mode (all `mode.fixed*` and `mode.height` unsupported), no raw measurement output, no RTCM. `rtcmBaseID` is unsupported.
- Antenna cable delay, minimum elevation, and time GNSS realize requests exactly; time pulse width is quantized to 1 us. Factory configuration matches the gen 9 profile (cable delay 50 ns, minimum elevation 5, time grid UTC).
- The as-found factory time grid is UTC, so `timeGNSS` is absent from readback until something sets a GNSS-aligned grid; the first probing run trips the --pps grid side effect in `BUGS.md` and reports itself not-left-as-found once.

## Signals

Discovered supported set: GPS L1, GAL E1, GLO L1, QZSS L1+L1S, SBAS L1 - single band, as expected for an M10. BDS is missing from the set because of the B1I/B1C mutual exclusion in `BUGS.md`: the receiver supports either BDS signal but not both at once (verified by direct VALSET), and the --gnss BDS expansion always requests both, so every BDS-involving request is refused - including the all-constellations request, whose VALSET also carries both keys - and the signal characterization carries those refusals verbatim. Re-vet the signal entry once BDS is reachable.

## Testing notes

The receiver identifies as EVK-M101 (the evaluation kit, not the module). The kit's front-panel switch must be in position 0 for the host UART to reach the receiver; in other positions the receiver transmits but its RX accumulates frame errors until it latches "UART1 RX disabled" (visible as a GNTXT message), after which only a power cycle recovers it - satpulsetool then sees NMEA but gets no answer to any poll. A full default run takes about 7 minutes; consecutive runs produce identical characterizations and exit 0.
