# AT6558D (URANUS5 V5.3.0.0)

CASIC V5 single-band navigation receiver, UART resting at 9600 (the
session raises to 115200). Characterized 2026-07-21 (disruptive);
baseline `AT6558D,0000000000000-URANUS5,V5.3.0.0.json`. Same firmware
as the ATGM332D-5N71 characterized 2026-06-13 (see its note), but not
identical behavior: this unit accepts single-constellation signal
sets the 5N71 refused, and its PCAS06 hardware string is
`AT6558D,0000000000000` where the 5N71's was empty.

## Limitations relative to the model

- Signals: GPS L1, BDS B1I, GLO L1 (no signal selection capability;
  the set is reported, not configurable per signal).
- Leap second output (`leap`): not delivered. Pulse-time (`tp` via
  TIM-TP) is delivered.
- Raw output (`obs`, `nav`): acknowledged but never emitted (the V5
  firmware limitation the casictool notes record).
- RTCM output: nothing is ever emitted. rtcmBaseID does not exist.
- Fixed position: LLH requests realized as ECEF (LLH and height never
  read back).
- Time pulse width quantized to 1 us.
- Save granularity: one group covering antenna cable delay, message
  output, minimum elevation, mode, and pulse width - except timeGNSS,
  which does not persist at all (an unsaved-able property).
- Active port: not identifiable (one port-query response per UART).

## Notes

- The wired UART is port 0; a second UART (port 1) exists and its
  stored speed is independent.
- After a reload, the CFG-PRT readback reports the restored (stored)
  baud while the UART keeps running at the pre-reload speed: stored
  configuration and the live line lawfully diverge until the speed is
  next set. Speed rediscovery must trust the speed the receiver
  answers at, not the readback (gpshwtest does, since 2026-07-21).
- Starting state for characterization runs: running 9600, binary mode
  with pos+time output (`--nmea-out none --pvt-out pos,time,off`).
